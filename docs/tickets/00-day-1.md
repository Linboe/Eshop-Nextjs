# Day 1 tickets (everyone)

## 01: Project setup, database and layout
**Owner:** Everyone   **User stories:** none   **Blocked by:** nothing

### What to build
The base that every other ticket stands on. When this is done, both of us can run the app, the database has tables and test data, the tests can run, and every page shares the same header, footer and look from `docs/design/`.

This ticket needs a few libraries. Ask before installing each one: `postgres` (postgres.js), `vitest@3`, `@supabase/supabase-js`, and a Supabase package for cookies in Route Handlers if we agree we need one.

- `db/setup.sql`: the four tables from `docs/ER.md` (`profiles`, `products`, `orders`, `order_items`) with their checks and delete rules, row level security turned on for every table with no policies, and about 16 to 20 test products across the five categories (lighting, furniture, textiles, decor, tableware)
- `lib/db.ts`: connects to Supabase Postgres with postgres.js and exports `sql`
- `.env.example`: the names of all variables with no values. `.env` is never committed
- Vitest 3 with `vitest.config.ts` (loads `.env` with `loadEnv` from vite) and one test that fetches `/` and checks the status
- Layout: colors, fonts and spacing from `docs/design/`, a header (logo, category links, a place for the cart count, a place for Log in / Log out) and a footer. The cart count and the login link are filled in by later tickets
- One customer account made by hand in Supabase (Authentication, Users, Add user, Auto Confirm User). Its email and password go in `.env` as `TEST_USER_EMAIL` and `TEST_USER_PASSWORD`

### Acceptance criteria
- [ ] `npm run dev` shows the layout with header and footer in the Cozy Co look
- [ ] After running `db/setup.sql` in Supabase, the four tables exist, row level security is on for each, and `products` has test data in all five categories
- [ ] A page can read from the database through `lib/db.ts` (checked by hand once)
- [ ] `.env.example` lists every variable name, and `.env` is in `.gitignore`
- [ ] `npm test` passes with the one test, and fails if the test is changed to expect a wrong status (break it once to check)
- [ ] Both teammates can clone the repo, add their own `.env`, and run the app

### Done when
- [ ] Every criterion passes, checked by hand, and the tests and the build pass
